# 입력 경로 하나를 미루며 느슨하게 둔 서버 검증은, 다른 경로의 규칙을 올릴 때 함께 올라가지 않는다

## 무슨 일이 있었나

상품 규정 정보(원산지·부가세유형·성인상품여부)의 필수 여부가 입력 경로마다 달랐다. 폼은 필수였고 엑셀과 서버는 선택이었다. 이 상태가 약 7주(2026-09-04 ~ 10-26) 이어졌다.

| 날짜 | 커밋 | 상품 폼 | 엑셀 | 서버 |
|------|------|---------|------|------|
| 07-19 | `03e5ebf` 폼에 규정 정보 섹션 추가 | 선택 | 컬럼 없음 | 검증 없음 |
| 09-04 | `54113c0` 규정 정보를 필수로, 기본값 지정 | **필수** | 컬럼 없음 | 검증 없음 |
| 09-11 | `a90e19b` 상품 쓰기 값 검증 스키마 추가 | 필수 | 컬럼 없음 | **세 값 모두 `required: false`** |
| 10-26 | `89850a5` 엑셀 컬럼 추가 + 서버 필수 | 필수 | 필수 | 필수 |

그 결과 엑셀로 등록한 상품만 세 값이 빈 채 저장됐고, 서버도 이를 받아들였다. 같은 "상품"인데 입력 경로에 따라 규정 정보가 있거나 없었다.

## 왜 그렇게 됐나 — 각 단계는 그 시점에 맞았다

1. **07-19 스펙**은 엑셀 반영을 "다음 라운드"로 미루고, 필드를 optional로 둔 근거를 적었다: *"Excel 대량등록 경로가 이 필드들을 아직 채우지 못하는 기간에도 데이터 정합성 문제가 없어야 하기 때문"*. 엑셀이 못 채우는 동안 서버가 필수를 요구하면 엑셀 등록이 전부 막히므로 옳은 판단이었다.
2. **09-04**에 폼만 필수로 올렸다. 폼 화면의 문제로 다뤘고, 엑셀·서버는 범위 밖이었다.
3. **09-11** 서버 쓰기 스키마를 만들 때 07-19의 전제("엑셀이 못 채운다")가 여전히 사실이어서 선택으로 두었다. 이것도 그 시점에는 맞았다 — 필수로 두면 엑셀 등록이 400으로 막혔다.
4. "다음 라운드"는 착수되지 않았다. 느슨함의 **원인(엑셀 미반영)**은 스펙에만 적혀 있었고, **결과(서버 optional)**는 코드에 주석 없이 남았다.

어느 단계도 틀리지 않았는데 전체는 어긋났다. 원인과 결과가 서로 다른 곳에 기록돼 있어, 폼 규칙을 올리는 순간 "서버가 왜 선택인지, 이제 올려야 하는지"를 물을 계기가 없었다.

## 원칙

**입력 경로 하나를 미루려고 서버 검증을 느슨하게 둘 때는, 그 느슨함이 임시라는 사실을 서버 검증 코드 자리에 남긴다.** 스펙에만 적으면 서버 스키마를 고치는 사람이 보지 못한다.

- 현재 `productWriteSchema.ts`는 반대 방향으로 그 기록을 남겼다: *"규정 정보 셋은 엑셀 대량등록이 채우지 못하던 동안 선택이었다. 상품 폼이 필수로 받는 값이다."*
- 한 경로(폼)의 필수 여부를 바꿀 때는 같은 데이터를 쓰는 **모든 입력 경로와 서버**를 표로 놓고 맞춘다. 상품은 폼(생성·수정·연동상품 수정 — [`same-form-three-screens-three-validation-mechanisms.md`](same-form-three-screens-three-validation-mechanisms.md)), 엑셀 템플릿, 엑셀 저장 전략, 서버 쓰기 검증(`findProductWriteViolation`) 네 층이다.
- 미룬 경로를 채우는 라운드에서는 **서버 검증을 올리는 것까지가 완료 조건**이다. 엑셀 컬럼만 추가하고 서버를 선택으로 두면, 옛 양식 파일이나 다른 클라이언트가 빈 값을 계속 넣을 수 있다.

## 이번 수정에서 정한 것

- 엑셀 템플릿에 `원산지`·`원산지(기타)`·`부가세유형`·`성인상품여부` 컬럼을 추가했다. `원산지(기타)`는 원산지가 '기타'일 때만 필수라 `requiredWhen` 속성을 새로 만들었다(`.claude/rules/excel.md`).
- 엑셀은 폼과 달리 기본값(과세·일반상품)을 채우지 않는다. 빈 값이면 미리보기에서 막고, 거기를 지나도 서버가 거부한다.
- 서버 쓰기 검증은 세 값을 필수로 올렸고, 원산지가 '기타'인데 직접 입력값이 비어 있으면 거부한다. 수정(PATCH)은 보낸 필드만 검사하므로 세 값이 빈 기존 상품도 다른 필드는 고칠 수 있다.
- 이미 빈 값으로 저장된 엑셀 상품은 백필하지 않고 사용자가 화면에서 채운다(2026-10-26 사용자 결정).
- 옛 양식 파일에는 새 필수 컬럼이 없어 `MISSING_FIELD`로 미리보기가 막힌다. 양식을 다시 받아야 한다.

## 남은 것

상품정보제공고시(`informationDisclosure`)는 엑셀이 여전히 받지 않는다. 사용자가 *"상품정보고시는 다음에 따로 다룸"*이라 미뤘다 — 이번 라운드 범위 밖으로 따로 다룬다는 뜻이다. 이 항목도 같은 구조에 놓여 있다. 서버는 `informationDisclosure`를 필수로 두지만 모양(`key`·`id`·`name`·`fields`)만 보므로, 엑셀 전략이 보내는 빈 값(`{ key: '', id: '', name: '', fields: {} }`)도 통과한다. 착수할 때 서버가 내용까지 요구하도록 함께 맞춘다.
